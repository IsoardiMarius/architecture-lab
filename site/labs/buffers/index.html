Buffers

A buffer is a temporary waiting area for data. It lets one part of a computer continue working while another part is not ready yet.

01 / Start from zero

What is a buffer?

A buffer is a temporary place where data waits before another part of a system can use it.

Imagine watching a video on your phone. Your phone downloads a few seconds of video before displaying them. If your Wi-Fi slows down for a moment, it can keep playing what is already stored. That temporary waiting area is a buffer.

Six words to understand first

Data
Information a computer handles: a photo, a letter, part of a video, or a measurement.
Memory (RAM)
The computer's fast, temporary working space. Many buffers live in RAM; some systems also buffer data on disk.
Producer
The part that creates or sends data. For a video, it could be the network delivering video pieces.
Consumer
The part that uses the data. For a video, it could be the player displaying each frame (picture).
Capacity
The maximum amount a buffer can hold. A buffer is never infinitely large.
Queue / FIFO
A queue is a waiting line. FIFO means First In, First Out: the first item added is the first one taken out. Not every buffer is FIFO.

An everyday analogy

In a restaurant, a cook prepares a meal and leaves it on a counter until a waiter picks it up. The cook is the producer, the waiter is the consumer, and the counter is the buffer.

Where the analogy stops: computer buffers can contain bytes rather than whole meals, can use different ordering rules, and can fill up. A larger counter cannot make the waiter work faster.

02 / The mechanism

Create → wait → use

  1. Data arrives. A producer sends some data. It is not ready to be used immediately.
  2. The buffer holds it. The data occupies some of the limited available space.
  3. The consumer takes it. When the next part is ready, it reads or processes the data, making space for new data.

What if the two sides work at different speeds?

A short rush

More data arrives than can be used for a few moments. This is a burst. The buffer absorbs the temporary excess.

Things slow down

Data leaves the buffer faster than new data arrives. The buffer drains (becomes emptier).

The rush never stops

If the producer stays faster, the buffer eventually fills. More memory only delays the problem.

A small calculation

A byte is a basic unit of data. One MB (megabyte) is approximately one million bytes. MB/s means megabytes per second: a rate, not a storage size.

A producer sends 2 MB/s, but the consumer can only use 1.5 MB/s. The buffer gains 0.5 MB every second. With 10 MB of free space, it fills in about 20 seconds (10 ÷ 0.5).

This assumes constant rates, an initially empty buffer, and no overhead. The important lesson: the buffer does not fix a permanent speed difference.

What happens when it is full?

The system needs a rule. It may make the producer wait, ask it to slow down (called backpressure), reject or drop new data, or temporarily store data elsewhere (called spilling to disk when it uses a storage drive). The right choice depends on whether losing data is acceptable.

04 / Three real-world situations

Where do buffers help?

Example 01 · Everyday life

Streaming a movie on your phone

Situation: the video player has already downloaded 5 seconds of video. Your connection briefly stops for 2 seconds.

What the buffer does: the player can keep showing pictures using the video already stored. It does not need to wait for the next download immediately.

Limit: if the connection stays slow long enough, the stored video runs out and playback may pause. Buffering reduces short interruptions; it cannot create new Internet bandwidth.

Example 02 · A busy website

100 requests arrive, but the server can handle 80

Situation: an application receives 100 tasks per second for 5 seconds, but workers can finish only 80 per second. A request is work asked of a server; a worker is a program doing that work.

What the buffer does: if a waiting queue accepts all the tasks, about 100 tasks accumulate (20 extra per second × 5 seconds). The workers can catch up after traffic drops.

Limit: if 100 tasks keep arriving every second forever, the queue grows until capacity is exhausted. You must reduce incoming work or increase processing capacity.

Example 03 · A TCP connection

One piece is missing, but later pieces arrive

Situation: a computer sends pieces of data numbered 1, 2, 3, 4, 5. Piece 3 is lost on the network; pieces 4 and 5 still arrive.

What the buffer does: the receiving computer can temporarily keep 4 and 5 while TCP recovers the missing piece 3. The program using the connection then receives the data in the correct order.

Limit: this ordering can delay a program even when newer data has arrived. This is called Head-of-Line Blocking: newer data waits behind missing older data.

And inside Linux or a database?

An operating system (such as Linux) manages a computer's programs, memory and devices. Its kernel is the central part that coordinates these resources.

NameWhat it holdsWhy it exists

PostgreSQL shared_buffersDatabase pages, meaning blocks of database data, held in shared RAM.Lets the database work with pages in memory instead of fetching every page from storage.

Buffer, queue, and cache are not identical. A buffer generally smooths timing; a queue organizes waiting items; a cache keeps data that may be reused. One system can combine these functions.

If you see Linux settings called tcp_rmem or tcp_wmem, they influence TCP buffer memory. These are operating-system details to explore later; you do not need to understand them to grasp buffering.

05 / Why bigger is not always better

What does a buffer cost?

A buffer helps with temporary mismatches in timing. It does not make a slow consumer faster.

  • Memory: a larger buffer usually occupies more working memory (RAM).
  • Latency: this means the time you wait for a result. A long waiting line may increase latency because data spends more time in the buffer.
  • Throughput: this means the amount of work completed per second. Increasing the waiting area does not automatically increase throughput.
  • Backpressure: when the system cannot keep up, it slows down or blocks the part sending more work. That protects capacity but may make the sender wait.
  • Dropping: discarding new or old data may be acceptable for an outdated live-video frame, but not for a payment record.

How would an architect decide?

Short traffic spike: add a reasonably sized buffer and a policy for what happens when it fills. Permanent overload: improve processing capacity, reduce demand, or accept a limited service. Merely raising the buffer limit postpones the problem.

Remember: buffering buys time, not unlimited processing power.
06 / Active recall

Questions you should answer

Try to answer aloud before revealing the explanation. Start with ordinary words, then introduce the technical term.

Start simple

01What is a buffer? Give one everyday example.

It is temporary storage where data waits. A video player may download several seconds of video in advance so playback can continue during a short network slowdown.

02Who are the producer and consumer?

The producer creates or sends data. The consumer reads or uses it. For streaming, the network supplies video and the player displays it.

03What does buffer capacity mean?

Capacity is the maximum amount of data the buffer can hold. When all its space is occupied, it cannot accept more without another action.

Explain the mechanism

04What happens when a producer stays faster than the consumer?

Data accumulates until the buffer fills. A bigger buffer delays this outcome but does not fix the permanent difference in processing speed.

05What is backpressure in everyday words?

The system tells the sender to slow down or makes it wait because there is not enough space for more data.

06What is the difference between a buffer, a queue and a cache?

A buffer temporarily holds data between steps. A queue is an organized waiting line, often first-in-first-out. A cache keeps reusable data so it can be accessed faster. One system may do more than one of these jobs.

07If 2 MB arrive each second and only 1.5 MB leave, how long to fill 10 MB of free space?

0.5 MB accumulate each second. 10 MB ÷ 0.5 MB/s = approximately 20 seconds, assuming steady rates.

08Why can a video continue briefly when Wi-Fi stops?

It can play video data that was downloaded earlier and is waiting in a buffer. When the buffer runs out, playback may stop.

Think like an architect

09Why might a larger buffer make a service feel slower?

It allows more work to wait. Each request can spend longer in line before the application processes it, increasing latency (waiting time).

10A website is permanently overloaded. Would you only increase its buffer?

No. A buffer can absorb a short spike, but permanent overload requires more processing capacity, less incoming work, or a policy to reject some requests.
