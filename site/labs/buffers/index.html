Buffers

A buffer is temporary storage for data while it waits to be sent, received, processed, or consumed. It helps two parts of a system work at different rates.

01 / In one sentence

Why do buffers exist?

A buffer temporarily holds data because the producer and consumer may not run at the same speed or at exactly the same time.

Think of the counter between a restaurant kitchen and its waiters: a cook can put a finished plate down before a waiter is available to pick it up.

Analogy limit: the counter has a finite capacity. Adding a bigger counter does not make the waiters faster. Also, not every buffer follows a first-in, first-out (FIFO) order.

02 / Mechanism

Produce → store → consume

The producer puts data into the buffer. The consumer takes data out when it is ready. In a simple bounded queue, the buffer has a fixed number of slots. Real buffers may store bytes, pages, frames, or messages rather than discrete slots.

What happens when speeds differ?

Producer temporarily faster

The buffer fills. Short bursts can be absorbed without stopping the whole pipeline immediately.

Consumer catches up

The buffer drains. If empty, the consumer may need to wait for more data.

Producer stays faster

A finite buffer eventually fills. The system must wait, apply backpressure, reject, drop, or spill data, depending on its design.

Capacity example: producer = 2 MB/s, consumer = 1.5 MB/s. If the buffer starts empty and has 10 MB free, it fills at 0.5 MB/s and reaches capacity after about 20 seconds of sustained imbalance.

This simplified calculation assumes steady rates and no overhead or capacity changes.

05 / Architect decisions

A buffer is not a free performance boost.

  • Capacity vs memory: larger buffers absorb larger bursts but consume more memory.
  • Throughput vs latency: queued data may sit longer before being processed; bigger buffers can hide a sustained bottleneck rather than solve it.
  • Backpressure vs dropping: decide how a producer should behave when the buffer fills. That decision depends on whether data may be lost.
  • Buffer vs cache vs queue: a buffer smooths timing; a cache retains reusable data for faster access; a queue is a data structure or messaging abstraction often used to implement buffering. These categories can overlap.

Architecture example: an ingestion service handling short traffic spikes may need a bounded buffer and backpressure. If average incoming traffic permanently exceeds processing capacity, increasing the buffer only postpones overload.

06 / Active recall

Questions you should answer

Answer without reading the explanation. Open each answer only after you have tried.

Fundamentals

01What is a buffer, in one sentence?

Temporary storage for data waiting to be sent, processed, received, or consumed.

02Why does a buffer help when producer and consumer have different speeds?

It absorbs temporary differences in timing and lets either side operate without immediate synchronization. It cannot fix a permanent capacity mismatch.

03What is the limitation of the restaurant-counter analogy?

The counter is finite, and no buffer guarantees extra processing capacity. Also, real buffers are not always FIFO.

Mechanisms

04What can happen when a bounded buffer becomes full?

The producer may have to wait; the system may apply backpressure, reject or drop work, or spill to another storage tier. The policy is a design choice.

05Producer: 2 MB/s; consumer: 1.5 MB/s; free space: 10 MB. When does it fill?

Net growth is 0.5 MB/s, so it takes about 10 / 0.5 = 20 seconds under constant rates.

06How is a buffer different from a cache?

Buffering primarily smooths timing between stages; caching primarily retains data for reuse. They can overlap, and a queue can implement a buffer.

Architect choices

07Why might increasing a buffer worsen latency?

More items can wait in the queue. Under sustained load the queued work gets older, even while throughput stays unchanged.

08Why does receiving a later TCP segment not mean the application can read its bytes immediately?

TCP delivers an ordered byte stream. Missing preceding bytes create a gap; later data can be retained until the gap is filled. See the linked TCP example.
