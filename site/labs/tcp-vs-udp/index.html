Networking / Transport layer

TCP vs UDP

TCP (Transmission Control Protocol) and UDP (User Datagram Protocol) are two essential protocols operating at the Transport Layer (Layer 4 of the OSI model). They define how data is exchanged between applications over a network, but they use different mechanisms and provide different guarantees.

01 / Mechanism

TCP — Transmission Control Protocol

TCP is a connection-oriented and reliable protocol.

How it works

  • Connection-oriented: Before exchanging application data, the client and server establish a connection using a Three-Way Handshake (SYN → SYN-ACK → ACK).
  • Reliable delivery: TCP ensures that data is delivered to the application in the correct order, without duplication, as long as the connection completes successfully.
  • Retransmission: Lost data is automatically retransmitted.
  • Flow control: TCP adjusts the sending rate according to the receiver's capacity.
  • Congestion control: TCP regulates the transmission rate to reduce network congestion.

Common use cases

TCP is particularly suitable when data integrity, reliability, and ordering are essential.

  • Web browsing (HTTP/1.1 and HTTP/2).
  • File transfers (FTP, SFTP).
  • Remote access (SSH).
  • Email communication (SMTP, IMAP).

Python example

Python · TCP socket
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# Establish a TCP connection
sock.connect(("example.com", 80))

# Send data
sock.sendall(b"Hello")

sock.close()

This demonstrates a TCP socket connection, not a valid HTTP request. An HTTP server may reject or ignore the raw message.

Key takeaway: A TCP connection must be established before application data can be transmitted.
02 / Mechanism

UDP — User Datagram Protocol

UDP is a connectionless protocol that does not guarantee reliable delivery.

How it works

  • Connectionless: No connection establishment or Three-Way Handshake is required.
  • No delivery guarantee: Datagrams may be lost during transmission.
  • No ordering guarantee: Datagrams may arrive in a different order from the one in which they were sent.
  • No automatic retransmission: UDP does not automatically resend lost datagrams.
  • Low overhead: UDP has a smaller header (8 bytes compared to TCP's minimum of 20 bytes).

Common use cases

UDP is particularly suitable for applications that prioritize low latency, real-time communication, or lightweight message exchange.

  • Online multiplayer games.
  • Video conferencing and VoIP.
  • Traditional DNS queries.
  • HTTP/3 through QUIC, which implements its own reliability mechanisms on top of UDP.

Python example

Python · UDP socket
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)

# Send data without establishing a connection
sock.sendto(b"Hello", ("example.com", 12345))

sock.close()
Key takeaway: UDP allows applications to send datagrams directly without establishing a transport-layer connection.

05 / Architecture choices

When should we choose TCP or UDP?

In most modern applications, the transport protocol is already selected by the technology or framework being used.

  • An HTTP/1.1 or HTTP/2 client uses TCP.
  • An HTTP/3 client uses QUIC over UDP.
  • An SSH connection uses TCP.

However, when designing low-level networking systems, custom communication protocols, or performance-sensitive applications, we may need to explicitly choose between TCP and UDP.

The decision depends on several factors:

  • Reliability: Is guaranteed, ordered data delivery required?
  • Latency: Is minimizing communication delay a priority?
  • Packet loss tolerance: Can the application tolerate missing data?
  • Ordering: Must data arrive in the same order it was sent?
  • Complexity: Can the application implement its own reliability, ordering, or congestion-control mechanisms?

Architecture examples

File transfer

TCP is generally preferred because missing or incorrectly ordered data must be handled reliably.

Real-time gaming

UDP is often preferred because the latest player position can matter more than retransmitting an outdated update.

Video conferencing

UDP is commonly used because receiving audio and video on time is often more useful than recovering every lost packet.

06 / Active recall

Questions you should answer

Try explaining each answer aloud before opening it. The goal is to explain the mechanism and justify a design choice — not memorize a definition.

Fundamentals

01What does “connection-oriented” mean in TCP?

TCP establishes shared connection state before exchanging application data. The three-way handshake is SYN → SYN-ACK → ACK. UDP has no equivalent transport handshake.

02How is a TCP byte stream different from a UDP datagram?

TCP delivers an ordered stream of bytes with no application message boundaries. UDP preserves the boundaries of individually sent datagrams, but delivery and ordering are not guaranteed.

03Does TCP guarantee that every packet will arrive?

No. TCP retransmits lost data and presents an ordered, duplicate-free byte stream while communication succeeds. A connection can fail; applications must detect errors and decide how to recover.

Mechanisms

04What happens when a TCP segment is lost? What about UDP?

TCP can detect missing acknowledgments or other loss signals and retransmit unacknowledged data. UDP does not have automatic transport-layer acknowledgments or retransmission; an application can implement its own recovery.

05What is the difference between flow control and congestion control?

Flow control protects the receiver from being overwhelmed. Congestion control protects the network path from excessive traffic. Both affect TCP sending behavior for different reasons.

06Is UDP always faster, or inherently less secure?

Neither. UDP has less protocol overhead, but performance depends on the whole system and network conditions. Neither UDP nor TCP encrypts data by itself; security comes from additional protocols, such as TLS or QUIC.

07How can HTTP/3 offer reliable communication over UDP?

HTTP/3 uses QUIC over UDP. QUIC implements reliable streams, loss detection, congestion control and TLS 1.3 security above UDP, rather than relying on TCP.

Architect decisions

08Why would a video call prefer losing a frame to retransmitting it?

A retransmitted frame may arrive after its playback deadline, increasing latency or disrupting audio/video synchronization. Timely delivery of current media can matter more than recovering outdated data. Applications still need strategies for acceptable quality.

09Why use TCP for SSH, but often UDP for a DNS query?

SSH needs an ordered, reliable stream for interactive remote access. Traditional DNS queries are usually short independent request/response exchanges, so UDP avoids a transport handshake. DNS also uses TCP when appropriate, including zone transfers and some larger responses.

10When designing a service, who really chooses TCP or UDP?

Often the application protocol or library makes the choice for you (for example, SSH or HTTP/3). For a custom transport, choose based on loss tolerance, latency, reliability, ordering, ecosystem support and the complexity of implementing missing mechanisms.

07 / Summary

Key takeaways

TCP prioritizes reliability and ordered delivery, while UDP provides a lightweight, connectionless transport without built-in delivery guarantees.

  1. TCP is not always slower than UDP. Performance depends on the application, network conditions, and protocol implementation.
  2. UDP is not inherently less secure than TCP. Neither TCP nor UDP provides encryption by itself.
  3. UDP does not necessarily mean unreliable applications. Protocols such as QUIC implement reliability, congestion control, and encryption on top of UDP.

From an architect's perspective: The choice is not simply about speed versus reliability. It is about selecting the transport mechanisms that best match the application's requirements and constraints.
